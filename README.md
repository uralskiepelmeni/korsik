# Корсик — HR-бот адаптации в мессенджере МАКС

Бот отвечает на вопросы новых сотрудников **дословными цитатами из корпоративных документов**:
находит нужный пункт, показывает его текст и указывает источник («Правила внутреннего трудового
распорядка, п. 6.1.9, стр. 5»). Если ответа в документах нет — честно говорит об этом и передаёт
вопрос кадровой службе.

Ничего не выдумывает: ответ — это найденный пункт, а не сгенерированный текст.

---

## Что внутри

| Компонент | Файл | Что делает |
|---|---|---|
| Сервис ответов | `app/service.py` | поиск по базе знаний, проверка фрагмента моделью, опросы, обращения, роли, панель |
| Бот МАКС | `bot/max_bot.py` | диалог в чате, меню кнопками, опросы, приём документов от HR |
| Планировщик | `bot/scheduler.py` | рассылки по календарю адаптации, «3 вещи на сегодня» руководителю |
| Сборка индекса | `scripts/build_index.py` | считает эмбеддинги по `data/kb.jsonl` |
| База знаний | `data/kb.jsonl` | 199 фрагментов из 4 документов: ПВТР, антикоррупционная политика, политика качества, коммерческая тайна |

### Как принимается решение об ответе

```
вопрос → эмбеддинг (bge-m3) → 8 ближайших фрагментов → модель-верификатор (d3-nano)
       → уверенность ≥ 0.60 ? цитата с пунктом : «в документах нет» → обращение в HR
```

Модель-верификатор смотрит на пару «вопрос + фрагмент» и отвечает, содержится ли в фрагменте ответ.
Порог отсекает неуверенные ответы — это и даёт ноль выдуманных ответов.

## Требования

- Python **3.11+** (проверено на 3.14)
- **GPU рекомендуется:** с видеокартой от 8 ГБ (проверено на A10G 24 ГБ) — ответ за 0.4 с.
  Модели в половинной точности занимают ~6 ГБ видеопамяти.
  Без GPU тоже работает: 3–8 с на вопрос, но нужно больше ОЗУ (см. ниже)
- ОЗУ (только если без GPU): **16 ГБ** при работе на CPU — модель-верификатор в обычной точности занимает ~9 ГБ,
  эмбеддинги ещё ~2.3 ГБ. Если памяти меньше, поставьте `KORSIK_VERIFIER_DTYPE=bfloat16`
  (вдвое меньше, ~4.5 ГБ), тогда хватит 8 ГБ
- Диск: **~12 ГБ** на модели (bge-m3 ≈ 2.3 ГБ, d3-nano ≈ 5 ГБ, остальное — окружение)
- GPU не обязателен. На CPU ответ занимает **3–8 секунд**, на GPU (≥8 ГБ) — **0.4 секунды**
- Для распознавания сканов: `tesseract-ocr` с русским языком и `poppler-utils`

## Установка

### 1. Зависимости системы

```bash
# Debian / Ubuntu
sudo apt update
sudo apt install -y python3-venv python3-pip tesseract-ocr tesseract-ocr-rus poppler-utils

# macOS (Homebrew)
brew install tesseract tesseract-lang poppler
```

### 2. Окружение Python

```bash
git clone <адрес-репозитория> korsik
cd korsik

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install --upgrade pip
pip install -r requirements.txt
```

### 3. Настройки

```bash
cp .env.example .env
```

Откройте `.env` и заполните:

- `MAX_TOKEN` — токен бота (см. ниже);
- `KORSIK_PANEL_TOKEN` — **обязательно смените** (`change-me` оставлять нельзя): по этому коду
  команда `/bootstrap <код>` выдаёт роль администратора;
- `KORSIK_DEVICE` — `cuda` или `cpu`, если автоопределение не подходит;
- `KORSIK_API` — адрес сервиса, по умолчанию `http://127.0.0.1:8000`.

Переменные можно не прописывать в `.env`, а экспортировать в оболочке — поддерживаются оба способа.

### 4. Сборка индекса (один раз, ~2–5 минут)

```bash
python scripts/build_index.py
```

Скрипт скачает модель эмбеддингов и создаст `data/index.json` и `data/emb.npy`.
При первом запуске скачивание моделей может занять 10–20 минут.

## Получение токена бота

1. Откройте в МАКС бота **@MasterBot**.
2. Создайте бота (или возьмите существующего) на верифицированный профиль организации.
3. Скопируйте access token — он нужен в `MAX_TOKEN`.

Бот работает через **long polling** (`GET /updates`), поэтому публичный HTTPS и вебхук не требуются:
достаточно, чтобы машина с ботом имела доступ в интернет.

## Запуск

Нужны два процесса: сервис ответов и бот.

**Терминал 1 — сервис:**

```bash
source .venv/bin/activate
python -m app.service
```

Проверка: `curl http://127.0.0.1:8000/health` → `{"ok":true,"chunks":199,...}`

**Терминал 2 — бот:**

```bash
source .venv/bin/activate
python -m bot.max_bot
```

В логе появится `бот: 200` и `старт long polling` — можно писать боту в МАКС.

### Порядок первого запуска

1. Напишите боту в МАКС `/start` — придёт приветствие с меню.
2. Назначьте себя администратором: `/bootstrap <KORSIK_PANEL_TOKEN>`.
3. В меню появятся разделы для кадровой службы: обращения, сотрудники, конструктор опросов, сводка.

### Роли

| Роль | Что может |
|---|---|
| `employee` | задаёт вопросы, проходит опросы, видит документы уровня «для всех» |
| `manager` | всё как у сотрудника + видит своих новичков и получает «3 вещи на сегодня» |
| `hr` | обращения (ответ, закрытие), загрузка документов, сотрудники, опросы, сводка |
| `admin` | всё как у HR + назначение ролей и документы любого уровня |

Назначение роли: `/role` — меню кнопками (только для администратора) или
`/role <user_id> <employee|manager|hr|admin>`. Свой `user_id` — командой `/whoami`.

## Работа с документами

HR может добавить документ прямо в чат: пришлите файл **PDF, DOCX, PPTX или TXT**.
Бот скачает его, извлечёт текст (для сканов — OCR), нарежет по пунктам и проиндексирует.

Уровень доступа задаётся подписью к файлу:

- без подписи — документ видят все;
- в подписи есть `hr` — только кадровая служба и администратор;
- в подписи есть `admin` — только администратор.

Если в документе нет нумерации пунктов, он режется на окна по 1200 символов,
и цитата ссылается на «фрагмент N».

---

## Опросы

Четыре опроса из ТЗ уже заведены: 3-й рабочий день, чек-лист двух недель,
опрос через месяц и итоговый. Плюс конструктор: HR собирает свои опросы кнопками.

Правило из ТЗ работает: оценка **ниже 8** или ответ **«нет»** → бот просит причину.
Ответы видны в сводке (`/digest`), причины размечаются по темам.

## Календарь адаптации

14 событий: за 2 дня до выхода, за день, первый день (приветствие, карта, техника,
знакомство с компанией, итог дня), второй день, третий, 14 дней, месяц, 51-й день,
конец испытательного срока. Руководителю в дни −1, 1, 3, 30 уходит «3 вещи на сегодня».

**Демо-режим:** `KORSIK_DEMO=1` — одна минута равна одному дню адаптации.
Удобно показывать календарь за несколько минут. В обычном режиме — по реальным датам.

Завести сотрудника: в меню HR «Сотрудники» → «Как завести сотрудника»
(нужны `user_id`, площадка, дата выхода, имя). Привязать руководителя — там же.

## Панель

`http://127.0.0.1:8000/panel?token=<KORSIK_PANEL_TOKEN>` — документы с уровнями,
пользователи и роли, последние события.

## Полезные эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | состояние, число фрагментов |
| POST | `/ask` | `{"user_id":"1","text":"вопрос"}` → ответ или отказ |
| GET | `/documents?user_id=` | документы, доступные роли |
| GET | `/surveys?user_id=` | опросы и прогресс |
| POST | `/admin/upload` | загрузка документа (base64) |
| POST | `/admin/delete_doc` | удалить документ из базы |
| GET | `/digest?days=7` | сводка для HR |
| POST | `/roles/set` | назначить роль |

## Если что-то не работает

**`CERTIFICATE_VERIFY_FAILED` при обращении к МАКС.**
Платформа требует российский корневой сертификат. Скачайте его:

```bash
curl -o ru_root.crt https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt
```

и укажите в `.env`: `MAX_CA=/путь/к/ru_root.crt` (можно указать файл с цепочкой из нескольких).

**Бот молчит.** Проверьте, что сервис отвечает (`curl /health`), в логе бота есть `бот: 200`,
и что боту написали именно в МАКС (не в другой мессенджер).

**Ответ «в документах нет» на очевидный вопрос.** Скорее всего документа нет в базе —
проверьте `/documents`, при необходимости загрузите его через HR-меню.

**Не хватает памяти (`Killed`, `MemoryError`).** Модель-верификатор в обычной точности требует
около 9 ГБ ОЗУ. Добавьте в `.env` строку `KORSIK_VERIFIER_DTYPE=bfloat16` — потребление упадёт
примерно вдвое, качество ответов практически не меняется.

**Медленно на CPU.** Это ожидаемо: 3–8 секунд на вопрос. Для демонстрации можно держать
процесс запущенным постоянно, чтобы модели не загружались заново.

**Скан не читается.** Убедитесь, что установлены `tesseract-ocr-rus` и `poppler-utils`.

## Ограничения

- Качество ограничено базой знаний: 4 документа не покрывают питание, пропуска, транспорт, ДМС —
  на такие вопросы бот честно отвечает отказом и передаёт их кадровой службе.
- Точность измерялась на 33 перефразированных вопросах: правильный пункт с первого раза — 81,8 %,
  ложных ответов на 20 вопросов вне базы — 0. На других документах цифры будут иными.
- Порог уверенности 0.60 калиброван на сгенерированных вопросах; на живых данных его стоит пересчитать.
- OCR сканов возможен с ошибками распознавания.
